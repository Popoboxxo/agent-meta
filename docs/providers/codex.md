## What is Codex CLI?

OpenAI's terminal-based AI coding agent (Rust). Comparable to Claude Code: interactive
chat in the terminal, file operations, shell integration, subagents and hooks.
TOML-native: project config and agent definitions live in TOML files.

Context file: **`AGENTS.md`** (the cross-tool standard, same as Gemini/Opencode/ZCode/Kimi Code).
agent-meta writes its managed block into the shared `AGENTS.md` in the project root.

Registry key: **`Codex`**.

## Directory and file structure

```
AGENTS.md                  ← Project context + managed block (shared template)
rules/                     ← Rules directory (project root; .rules files)
.codex/
  agents/                  ← Sub-agents as TOML files (generated by agent-meta)
    developer.toml
    orchestrator.toml
    ...
  config.toml              ← Project config incl. MCP (mcp_servers)
  hooks/                   ← RESERVED PATH — NOT written by agent-meta (see Hooks)
  snippets/                ← Snippets (generated)
  pending-tasks.md         ← Lifecycle tasks (gitignored)
  3-project/               ← Extensions read by agents at runtime

~/.codex/
  config.toml              ← User-level config
  AGENTS.md                ← Global context (all projects)
  agents/                  ← Personal agents (auto-loaded, see below)
```

|---------|------------|-------|

| Config directory | `.claude/` | `.codex/` |

## Sub-agents in Codex

Codex agents are **TOML documents** in `.codex/agents/` — GA since 2026-03, auto-loaded
as config layers (personal `~/.codex/agents/` + project-scoped `.codex/agents/*.toml`,
no registration step; a custom agent wins over a same-named built-in).

**agent-meta generates via the `codex-toml` frontmatter mechanism** (data-driven
`agent-transform`, issue #629 — no `if provider == ...` branch):

```toml
name = "developer"
description = "Feature implementation and bugfixes..."
model = "gpt-5.4"                 # injected per role (model-tiers / overrides)
sandbox_mode = "workspace-write"  # static extra-field
developer_instructions = """
# developer
...
"""

# agent-meta provenance is preserved as TOML comments:
# version: 2.1.0
# generated-from: 1-generic/developer.md@2.1.0
```

Notes:

- The required body field is **`developer_instructions`** (V7 correction — not `instructions`).
- `model` is injected per role via the standard single-model resolution chain
  (`resolve_model()`): overrides → role defaults → tier presets.
- Claude-specific frontmatter (`memory`, `temperature`, ...) is stripped;
  the `tools` field is skipped (Codex agents do not take a frontmatter tool list).

**Dispatch:** native tools `spawn_agent` / `send_input` / `resume_agent` /
`wait_agent` / `close_agent` (V7). The `multi_agent` feature flag is stable
default-on (`agents.enabled` default true) → parallel fan-out works by issuing
multiple `spawn_agent` calls in one response.

## Project context (AGENTS.md)

Codex follows the `AGENTS.md` standard with **nearest-wins subdir semantics** (V3):

- Files are concatenated root → cwd, **closer files appear later** — a subdirectory
  `AGENTS.md` effectively overrides the root file.
- **Max 1 file per directory** (`AGENTS.override.md` > `AGENTS.md`; empty files skipped).
- `project_doc_max_bytes` = **32 KiB combined over the whole chain** — silent
  truncation risk for large managed blocks.
- Subdir files are appended *after* the managed block → they can counter-narrate it.
- **Untrusted projects may not load the root `AGENTS.md` at all** (0.150.0).
- Codex parses no managed-block markers → agent-meta's
  `<!-- agent-meta:managed-begin/end -->` markers cannot be corrupted.

agent-meta reuses the shared `templates/configs/AGENTS.project-template.md`
(same template as Gemini, Opencode, Mammouth, ZCode, Kimi Code).

## Hooks

Codex supports 12 lifecycle events (since v0.150.0) with Claude-identical names:
`PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`,
`SessionStart`, `SessionEnd`, `UserPromptSubmit`, `SubagentStart`, `SubagentStop`,
`Stop`, `Interrupt`.

The payload contract is **verified** (V1): stdin = one JSON object
(`session_id`, `transcript_path`, `cwd`, `hook_event_name` + Codex extensions
`model`, `turn_id`; tool events add `tool_name`/`tool_use_id`/`tool_input`),
blocking is synchronous by default, deny via
`hookSpecificOutput.permissionDecision: "deny"` (plus legacy exit 2 + stderr),
configuration via `hooks.json` **and** inline `[hooks]` (all locations run).

**agent-meta deliberately does NOT mirror hooks** (`has_hooks: true` only reserves
the `.codex/hooks/` path for collision tests; no `hook_protocol` — #630 pattern):

1. **Payload deviations vs Claude Code:** `continue` / `stopReason` /
   `suppressOutput` are unsupported for `PreToolUse`/`PermissionRequest`
   (parse → hook marked failed).
2. **Hash-trust review:** Codex skips non-hash-reviewed hooks until an interactive
   `/hooks` review (escape hatch: `--dangerously-bypass-hook-trust`) — mirrored
   scripts would not run by default.

`hook_protocol` can be enabled config-only once these deviations are handled.

## MCP

Codex reads `mcp_servers` from `.codex/config.toml` (STDIO + HTTP). agent-meta
configures `mcp-config: {committed-file: .codex/config.toml, format: codex-toml-mcp}`.

- **No secrets-file:** Codex has no include/import mechanism for a second TOML
  file (V8). The documented secrets strategy is **env-var indirection** in the
  committed config (`bearer_token_env_var`, `env_key`, `[mcp_servers.<id>.env]`).
- The `codex-toml-mcp` format writer **lands with the P3 commit**; until then
  sync warns and skips MCP generation for Codex.
- Verified precedence (V8): CLI flags > project config (root → cwd, closest wins) >
  profile > user > system > defaults; relative paths resolve against the `.codex/`
  directory. The exact cross-layer **merge semantics for `mcp_servers`** are an
  open P6 real-repo test.

## Model tiers

GPT-5.x family (state 2026-09). Tiers resolve per role into the agent TOML `model` field.

| Tier | Model ID |
|------|----------|
| `nano` | `gpt-5.4-mini` |
| `fast` | `gpt-5.4` |
| `balanced` | `gpt-5.3-codex-spark` |
| `powerful` | `gpt-5.5` |
| `max` | `gpt-5.6` |

Aliases (config `model-aliases`): `sol` → `gpt-5.6-sol`, `terra` → `gpt-5.6-terra`,
`luna` → `gpt-5.6-luna`. Per-role overrides via `model-overrides` in `project.yaml`.

## agent-meta configuration

### Activate Codex

```yaml
# .meta-config/project.yaml
ai-providers:
  - Codex
```

Or alongside other providers:

```yaml
ai-providers:
  - Claude
  - Codex
```

### Delegation

`config/delegation-syntax.yaml` maps the `{{PAL_*}}` placeholders to Codex syntax:
delegate via a native `spawn_agent` toolcall, collect via `wait_agent`; fan-out =
multiple `spawn_agent` calls in one response (multi_agent default-on); A2A handoff
as **JSON envelope** (`handoff_format: json`, envelope support verified).
Bootstrap: `file-based`, `action: none` — no registration step.

Tool whitelist (`config/provider-tools.yaml`, `codex`): `Bash`, `Read`, `Write`,
`Edit`, `Glob`, `Grep`, `WebFetch`, `WebSearch`, `Agent`, `mcp__*`.
`bash_tool_name: Bash` (canonical hook/matcher name; `apply_patch` matches as the
Edit/Write tool; internal names `shell`/`exec_command` are **not** whitelisted).
`TodoWrite` is dropped silently (no verified todo tool in the Codex catalog).

### What does agent-meta generate?

| Artifact | Behavior |
|----------|----------|
| `.codex/agents/*.toml` | Regenerated on every sync, stale files deleted |
| `AGENTS.md` (managed block) | Updated on every sync |
| `AGENTS.md` (rest) | Created once, then maintained manually |
| `rules/*.rules` | Generated (`has_rules: true`); `.rules` naming check = open P6 item |
| `.codex/hooks/` | Path reservation only — **nothing written** (no hook mirroring) |
| `.codex/config.toml` (MCP) | Planned — `codex-toml-mcp` writer lands with the P3 commit; until then sync warns + skips |
| `.agents/skills/` | Skills channel (Codex reads user → repo → directory) |
| `.codex/snippets/`, `.codex/pending-tasks.md` (gitignored), `.codex/3-project/` | Standard agent-meta artifacts |

## Deliberate limitations

1. **No hook mirroring** — payload deviations vs Claude Code + hash-trust review
   gate (V1, #630 pattern). `.codex/hooks/` is reserved but never written.
2. **No settings.json** — Codex has none; everything lives in `.codex/config.toml`
   (`has_settings: false`).
3. **No MCP secrets-file** — no include/import mechanism; env-var indirection is
   the documented strategy (V8).
4. **No slash commands** — surface unverified, `has_commands: false` (P6 item).
5. **No TodoWrite mapping** — no verified todo tool in the Codex tool catalog.
