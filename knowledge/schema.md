## Domain

`agent-meta-docs` — internal project documentation and knowledge base for the
agent-meta meta-repository (agent templates, sync.py, architecture, guides).

## Concept Types

Each wiki page's frontmatter `type:` field must be one of the values below.
Types are grouped by the OKF directory they live in — this bundle does not
nest concepts under `concepts/<type>/` subfolders; all pages of a directory
live flat in that directory, and `type:` records the finer-grained kind.

| `type:` value | Directory | Meaning |
|---|---|---|
| `Concept` | `knowledge/wiki/concepts/` | General project concept, term, or mechanism (e.g. a design idea, a pattern, a framework feature) |
| `Architecture` | `knowledge/wiki/concepts/` | Architecture-level concept describing structure, layering, or a system component |
| `API Reference` | `knowledge/wiki/entities/` | Reference documentation for a concrete interface, script, config schema, or tool |
| `Guide` | `knowledge/wiki/topics/` | How-to guide, howto, analysis, audit, or spec — practical or investigative write-ups organized by topic |
| `Session Conclusion` | `knowledge/wiki/sources/` | Summary of a completed work session (decisions made, what changed, follow-ups) |
| `Plan` | `knowledge/wiki/plans/` | Concrete, ordered implementation plan derived from a concept, REQ, or bug — produced by the `planner` role |

## Usage

`type:` in a page's YAML frontmatter must match one of the values above.
Entities, topics and sources are tracked separately under `knowledge/wiki/entities/`,
`knowledge/wiki/topics/` and `knowledge/wiki/sources/`. `knowledge/wiki/index.md` is the entry point;
`knowledge/wiki/log.md` is the append-only change log.

New concept types may be added here without a version bump (additive, non-breaking).
Removing or renaming an existing type is a structural change and requires user sign-off
(see `knowledge-curator` Don'ts).
